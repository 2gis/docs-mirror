Утилита 2GIS CLI (`dgCtl`) предназначена для получения файла с лицензией и загрузки, сохранения и восстановления артефактов, необходимых для установки и обновления сервисов программного комплекса <Brand />.

Артефакты установки включают в себя Docker-образы сервисов и данные, необходимые для работы сервисов.

См. подробнее о [жизненном цикле артефактов установки](../lifecycle).

## Архитектура {#architecture}

![Поведение аргументов dgctl apps to registry](/img/on-premise/dgctl-registry.png)

2GIS CLI разделяет получение артефактов установки на этапы:

1. Загрузка артефактов установки из интернета ([режим `pull`](#pull-mode)).
2. Установка сервисов из загруженных артефактов ([режим `restore`](#restore-mode)).

В качестве хранилища артефактов можно использовать S3-совместимое хранилище или файловую систему: см. настройку `storage.type` в [конфигурационном файле](./config).

Вы можете использовать аргументы `--only-apps`, `--only-data` и `--only-license`, чтобы выполнять операции только над образами приложений, данными или лицензией соответственно. Вы можете комбинировать эти аргументы, чтобы выбрать несколько типов артефактов.

## Режимы работы {#operation-modes}

2GIS CLI запускается в одном из режимов: `license`, `pull`, `restore`, `save` или `manifest`.

| Режим      | Нужен доступ в интернет | Откуда загружать                             | Типы целевых хранилищ                                                        |
| ---------- | ----------------------- | -------------------------------------------- | ---------------------------------------------------------------------------- |
| `license`  | Да                      | Серверы лицензирования <Brand />             | S3-совместимое хранилище<br />Файловая система                                 |
| `pull`     | Да                      | Серверы обновления <Brand />                 | S3-совместимое хранилище и реестр Docker<br />Файловая система и реестр Docker |
| `restore`  | Нет                     | Файловая система                             | S3-совместимое хранилище и реестр Docker<br />Файловая система и реестр Docker |
| `save`     | Нет                     | S3-совместимое хранилище<br />Файловая система | Файловая система                                                             |
| `manifest` | Нет                     | —                                            | —                                                                            |

Для режимов `license` и `pull` доступ в интернет нужен для обращения по адресам:

* `datagateway.api.2gis.com` — для получения файла лицензии и файла манифеста;
* `origin-disk.2gis.com` — для получения файлов приложений и данных.

### Режим `license` {#license-mode}

В режиме `license` утилита запрашивает файл лицензии с серверов <Brand /> и записывает его в выбранное хранилище. Подробнее см. в разделе [Установка сервиса лицензий](/on-premise-api-platform/installation#install-license).

Процесс получения лицензии включает в себя запросы к S3-совместимому хранилищу и работу через интернет:

1. Сервис лицензий генерирует файлы для запроса лицензии и размещает их в S3-совместимом хранилище.
2. Утилита 2GIS CLI считывает эти файлы из S3, формирует из них запрос и отправляет его через интернет.
3. По итогам обработки запроса возвращается лицензия, которую утилита 2GIS CLI записывает в S3-совместимое хранилище.
4. Сервис лицензий считывает файл лицензии и обновляет своё состояние.

:::warning

Если вы используете режим `license` на версии On-Premise 1.16.0 и ниже, добавляйте в команды аргумент `--with-license-v1`.

:::

### Режим `pull` {#pull-mode}

В режиме `pull` утилита:

* Загружает актуальные артефакты установки с серверов обновления <Brand /> в выбранное хранилище и (при необходимости) в реестр Docker.

  По умолчанию утилита загружает артефакты для компонентов, указанных в [конфигурационном файле 2GIS CLI](./config). Чтобы загрузить артефакты установки только для определённого сервиса, убедитесь, что в конфигурационном файле указан родительский компонент этого сервиса, и используйте аргумент `--services`. Даже при использовании этого аргумента информация в файле манифеста обновляется для всех сервисов.

  См. список названий компонентов и сервисов в [справке по командам и аргументам 2GIS CLI](./help).
  
* Записывает в лог размер выгрузки (образов сервисов, данных и т. д.) без учёта уже имеющихся в хранилище файлов (если не передан аргумент `--overwrite`).

  Чтобы узнать ожидаемый размер выгрузки, передайте в режиме `pull` аргумент `--dry-run`. Утилита не загрузит артефакты, а только запишет размер в лог. Совместимо с аргументами `--services`, `--only-apps` и `--only-data`.

* Создаёт файл манифеста в формате JSON, содержащий информацию обо всех сервисах, и размещает его в выбранном хранилище в директории `/manifests`.

:::tip

Разделяйте артефакты установки с помощью аргумента `--apps-to-registry` (см. [справку по командам и аргументам 2GIS CLI](./help)) — так Docker-образы сервисов помещаются в реестр Docker, а остальные артефакты — в хранилище выбранного типа. Это позволяет контролировать размещение артефактов и избегать их смешения.

:::

### Режим `restore` {#restore-mode}

В режиме `restore` утилита выполняет выгрузку артефактов установки из файловой системы-источника в выбранное хранилище и (при необходимости) в реестр Docker. Артефакты должны быть предварительно загружены в файловую систему-источник с помощью режима [`pull`](#pull-mode) или [`save`](#save-mode).

:::tip

Разделяйте артефакты установки с помощью аргумента `--apps-to-registry` (см. [справку по командам и аргументам 2GIS CLI](./help)) — так Docker-образы сервисов помещаются в реестр Docker, а остальные артефакты — в хранилище выбранного типа. Это позволяет контролировать размещение артефактов и избегать их смешения.

:::

При использовании файловой системы в качестве целевого хранилища [настройка `storage.type: fs`](./help) запуск утилиты в режиме `restore` требует монтирования двух папок: исходной и целевой.

:::warning

Если вы используете режим `restore` на версии On-Premise 1.16.0 и ниже, добавляйте в команды аргумент `--with-license-v1`.

:::

### Режим `save` {#save-mode}

В режиме `save` утилита загружает артефакты установки из выбранного хранилища в файловую систему. Артефакты должны быть предварительно загружены в хранилище-источник с помощью режима [`pull`](#pull-mode) или [`restore`](#restore-mode).

При использовании файловой системы в качестве целевого хранилища ([настройка `storage.type: fs`](./help)) запуск утилиты в режиме `save` требует монтирования двух папок: исходной и целевой. 

:::warning

Если вы используете режим `save` на версии On-Premise 1.16.0 и ниже, добавляйте в команды аргумент `--with-license-v1`.

:::

### Режим `manifest` {#manifest-mode}

Режим `manifest` используется для работы с манифестами в S3-совместимом хранилище при [чистке старых данных](../lifecycle#data-cleanup).

## Зависимости {#dependencies}

Для работы с утилитой 2GIS CLI вам понадобится:


* [Лицензия на программный комплекс <Brand />](../api-keys), которая позволяет получать артефакты установки, связанные с приобретёнными продуктами <Brand />. Чтобы получить лицензию, см. [инструкцию](../../installation#get-license).

* Хост с установленным Docker Engine — на этом хосте будет работать 2GIS CLI. Для работы утилиты в режимах [`license`](#license-mode) или [`pull`](#pull-mode) этот хост должен иметь доступ в интернет (до серверов <Brand />).

* В зависимости от выбранного типа хранилища:

  * S3-совместимое хранилище артефактов установки.
  * Свободное место на файловой системе хоста, предназначенного для 2GIS CLI.

* Реестр Docker, если он будет использоваться для хранения Docker-образов.
