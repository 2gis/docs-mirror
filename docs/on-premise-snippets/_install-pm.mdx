### 4.1. Перед установкой {#before-installing-pm}

1. Ознакомьтесь с:

   * [документацией Менеджера Платформы](/on-premise-api-platform/architecture/platform);
   * [архитектурой программного комплекса <Brand />](/on-premise-api-platform/architecture/solution-architecture);
   * [системными требованиями](/on-premise-api-platform/requirements).

2. Убедитесь, что выполнены предварительные шаги:

   1. [Подготовка к установке](#preparation).
   2. [Установка сервиса API-ключей](#install-keys).

3. Соберите данные, заданные или полученные на предыдущих шагах:

   | Объект                          | Пример значения                                | Как получить значение                                                             |
   | ------------------------------- | ---------------------------------------------- | --------------------------------------------------------------------------------- |
   | Endpoint реестра Docker для хранения образов сервисов             | `docker.registry.example.com`            | См. [Получение артефактов установки](#artifacts) |

4. Убедитесь, что удовлетворены требования к ресурсам, приведённые в [Helm-чартe](https://github.com/2gis/on-premise-helm-charts/blob/master/charts/platform/values.yaml).

   Подробнее о том, как это сделать, см. в разделе [Системные требования](/on-premise-api-platform/requirements).

   :::note[Используйте подходящий чарт]

   Содержание Helm-чарта, описанное в данном разделе, актуально для последней версии базовых сервисов (см. [Релизы базовых сервисов](/on-premise-api-platform/releases/core)). Чтобы изучить параметры для предыдущих версий, откройте [values.yaml в GitHub](https://github.com/2gis/on-premise-helm-charts/blob/master/charts/platform/values.yaml) и в списке тегов слева выберите тег `Core-<версия>`.

   :::

5. Определите доменное имя для сервиса Менеджер Платформы. Например, `platform.example.com`.

### 4.2. Установите Менеджер Платформы {#install-platform}

1. Создайте конфигурационный файл для Helm. Подробное описание доступных параметров см. [здесь](https://github.com/2gis/on-premise-helm-charts/blob/master/charts/platform/README.md).

   Пример файла содержит минимальные обязательные настройки и уже заполнен всеми необходимыми данными, собранными на предыдущих этапах.

   <details>
   <summary><code>values-platform.yaml</code></summary>

   ```yaml
   dgctlDockerRegistry: docker.registry.example.com

   imagePullSecrets: [onpremise-registry-creds]

   ui:
    brand: 2gis
    pages: "profile,signup,users,keys,license"

    oauth:
      wellknownUrl: https://platform-id.example.com/realms/Platform/.well-known/openid-configuration
      clientId: platform-client
      clientSecret: secret
      scope: ''
      codeUrl: https://platform.example.com/api/auth/code
      safeHosts: '.*'
      secure: true

    platform:
      api:
        url: 'https://keys-api.example.com'

    license:
      url: 'http://license'

    resources:
      requests:
        cpu: 300m
        memory: 384Mi
      limits:
        cpu: 1100m
        memory: 512Mi

    ingress:
      enabled: true
      className: nginx
      hosts:
        - host: platform.example.com
          paths:
            - path: /
              pathType: Prefix
      tls: []
      # - hosts:
      #   - platform.example.com
      #   secretName: secret.tls
   ```

   </details>

   Где:

   * `dgctlDockerRegistry`: endpoint вашего реестра Docker, в котором находятся образы сервисов программного комплекса <Brand /> в формате `HOST:PORT`.
   * `imagePullSecrets`: [Kubernetes Secrets](https://kubernetes.io/docs/concepts/configuration/secret/#using-imagepullsecrets) для доступа к реестру Docker, в котором находятся образы сервисов программного комплекса <Brand />.
   * `ui`: базовые настройки приложения.

     * `brand`: брендирование внутри приложения. Возможные значения: `2gis`, `urbi`.

     * `pages`: список доступных страниц в приложении. Значения записываются одной строкой через запятую и без пробелов, например, `'status,playground'`. Первое значение в списке — страница по умолчанию. Полный список возможных значений см. [здесь](https://github.com/2gis/on-premise-helm-charts/blob/master/charts/platform/README.md).

      * `oauth`: настройки интеграции с поставщиком OpenID Connect (OIDC). Требуется для аутентификации пользователей и работы со статистикой по API-ключам. В примере конфигурационного файла указаны значения для [Platform ID](/on-premise-api-platform/architecture/platform-id). Если вы используете собственного поставщика OIDC, укажите его значения.

        * `wellknownUrl`: URL до конфигурации OIDC.
        * `clientId`: идентификатор клиента OIDC.
        * `clientSecret`: секрет клиента OIDC для обмена кода авторизации на токен.
        * `scope`: области видимости (scopes) OIDC.
        * `codeUrl`: URL для обмена кода авторизации на токен. Формируется на основе фактического хоста приложения: `https://<host>/api/auth/code`.
        * `safeHosts`: регулярное выражение для валидации хоста, на который выполняется перенаправление после обмена токена.
        * `secure`: используется ли HTTPS для токенов аутентификации.
    
      * `platform`: настройки доступа к [сервису API-ключей](/on-premise-api-platform/architecture/keys):

        * `api.url`: хост сервиса в формате `HTTP(S)://HOST`.

      * `license`: настройки доступа к [сервису лицензий](/on-premise-api-platform/architecture/license):

        * `url`: хост сервиса в формате `HTTP://HOST`.

      * `resources`: настройки вычислительных ресурсов для сервиса. Чтобы узнать рекомендуемые значения ресурсов, см. [Вычислительные ресурсы](/on-premise-api-platform/requirements#resources).

      * `ingress`: конфигурация ресурса [Ingress](https://kubernetes.io/docs/concepts/services-networking/ingress/). Адаптируйте приведенную конфигурацию для соответствия используемому вами Ingress. **URL, указанный в параметре `ingress.hosts.host`, должен быть доступен извне вашего кластера Kubernetes, чтобы пользователи из приватного сегмента сети могли получить доступ к ресурсам по этому URL.**

2. (Опционально) Укажите дополнительные настройки — они позволят использовать вкладки Менеджера Платформы: [Песочницы](/on-premise-api-platform/platform-manager#working-with-playgrounds), [Стили карты](/on-premise-api-platform/platform-manager#managing-map-styles), [Статистика](/on-premise-api-platform/platform-manager#viewing-statistics) и [Мониторинг](/on-premise-api-platform/platform-manager#monitoring-services-status).

### 4.4. Настройте аутентификацию пользователей {#authentication}

Чтобы работать с Менеджером Платформы, конечные пользователи должны проходить аутентификацию. Программный комплекс <Brand /> предоставляет готовый сервис аутентификации для установки в закрытом контуре — Platform ID.

Вместо Platform ID вы можете использовать собственного поставщика OpenID Connect (OIDC) для авторизации пользователей по технологии единого входа (SSO). Аутентифицироваться и авторизоваться в Менеджере Платформы могут пользователи, зарегистрированные в базе внешнего поставщика OIDC. Управление пользователями также осуществляется на стороне этого поставщика.

Настройте поставщика OIDC:

1. Определите обязательные утверждения (claims) о данных пользователя. Следующие данные гарантированно должны быть заполнены в ответе `user-info`:

   * `sub` — идентификатор пользователя.
   * `email` — email пользователя.
   * `email_verified` — флаг, указывающий на то, был ли email подтверждён пользователем.
   * `name` — полное имя пользователя.
   * `phone_number` — номер телефона пользователя.

2. Настройте области видимости (scopes), по которым можно получать заданные утверждения (claims). Стандартно используются следующие scopes:

   * `openid` — обязательный параметр, указывающий на использование OpenID Connect для аутентификации пользователя.
   * `email` — email пользователя.
   * `profile` — ссылка на профиль пользователя.
   * `phone` — номер телефона пользователя.

3. Создайте клиента в вашем поставщике OIDC:

   1. Настройте идентификатор (`client_id`) и cекрет (`client_secret`) клиента.

   2. Укажите Callback URL и Logout URL для сервиса:

        * Callback URL: `https://{application_host}/api/auth/code`;
        * Logout URL: `https://{application_host}/api/auth/post_sign_out`.

   3. Настройте работу клиента с заданными на предыдущем шаге scopes.
