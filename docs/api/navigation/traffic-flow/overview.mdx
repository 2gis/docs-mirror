# Обзор

Traffic Flow API позволяет получать актуальные данные о трафике по дорожным сегментам региона. Вы можете наложить их на собственный дорожный граф для построения оптимальных маршрутов и расчёта времени в пути с учётом текущей ситуации.

Сервис предоставляет два типа данных:

* справочные данные о дорожных сегментах,
* динамические данные о дорожном трафике.

Данные предоставляются в виде отдельных файлов, разделённых по регионам и сериализованных в формате Protocol Buffers.

Traffic Flow API только поставляет детальные данные и не строит маршруты. Чтобы строить маршруты на карте, используйте [Routing API](/api/navigation/routing/overview).

## Доступные территории {#available-territories}

Данные доступны для следующих стран и городов:

* Азербайджан: Баку;
* Казахстан: Астана, Алматы, Актобе, Атырау, Караганда, Кокшетау, Костанай, Павлодар, Петропавск, Семей, Тараз, Уральск, Усть-Каменогорск, Шымкент;
* Кыргызстан: Бишкек;
* Россия;
* Таджикистан: Душанбе;
* Узбекистан: Ташкент.

Список доступных территорий может изменяться — уточняйте актуальные данные у [менеджера](#support).

### 1. Получите ключ доступа {#get-access-key}

Чтобы получить ключ доступа и работать с API, обратитесь в [отдел продаж <Brand />](https://dev.2gis.ru/api#form).

### 2. Получите манифест {#get-manifest}

Отправьте GET-запрос на endpoint `/manifest`. В заголовке `X-Api-Key` передайте ваш ключ доступа.

**Пример запроса:**

```bash
curl --request GET \
  --url 'https://traffic-flow.api.2gis.com/manifest' \
  --header 'X-Api-Key: API_KEY'
```

**Пример ответа:**

```json
{
  "manifest_time": "2026-10-05T12-58",
  "regions": [
    {
      "region_id": 32,
      "region_name": "moscow",
      "locations": {
        "etag": "3a4b5c6d7e8f90a1b2c3d4e5f6071829",
        "size": 1397503,
        "version": "2026-10-02T19-30"
      },
      "traffic_flow": {
        "etag": "229a67f07aaae766b2f7ab9625da078a",
        "size": 53692040,
        "version": "2026-10-02T19-38"
      }
    },
    ...
  ]
}
```

Где:

* `manifest_time` — время формирования манифеста в формате `YYYY-MM-DDThh-mm` (UTC).
* `regions` — массив регионов, доступных по вашему ключу. Каждый регион содержит:

   * `region_id` — идентификатор региона. Используется в запросах на скачивание данных. Регионы отвечают внутреннему формату хранения данных в <Brand /> и не связаны с субъектами Российской Федерации.
   * `region_name` — название региона.
   * `locations` — информация о файле со справочными данными о дорожных сегментах:

      * `etag` — ETag данных.
      * `size` — размер данных в байтах.
      * `version` — версия данных в формате `YYYY-MM-DDThh-mm` (UTC).

   * `traffic_flow` — информация о файле с данными о дорожном трафике:

      * `etag` — ETag данных.
      * `size` — размер данных в байтах.
      * `version` — версия данных в формате `YYYY-MM-DDThh-mm` (UTC).

#### Возможные ошибки при получении манифеста

| Код | Тип ошибки | Описание |
| --- | --- | --- |
| 401 | `unauthorized` | Ключ не передан или неизвестен. |
| 403 | `forbidden` | Ключ не прошёл проверку ограничений, заблокирован или в нём не настроены регионы. |
| 405 | `method_not_allowed` | Метод не поддерживается. |
| 429 | `too_many_requests` | Слишком много запросов, повторите запрос позже. |
| 500 | `internal` | Внутренняя ошибка сервера. |

### 3. Получите данные о дорожных сегментах {#get-locations}

Для каждого региона из манифеста отправьте GET-запрос на endpoint `/locations/{region_id}`, где `region_id` — идентификатор региона. В заголовках передайте:

* `X-Api-Key` — ваш ключ доступа.
* `If-None-Match` — ETag данных региона (`locations.etag`). 

    :::warning

    При первом получении данных не передавайте ETag в запросе: иначе вместо файла с данными вы получите код 304.
  
    :::

**Пример запроса:**

```bash
curl --request GET \
  --url 'https://traffic-flow.api.2gis.com/locations/32' \
  --header 'X-Api-Key: API_KEY' \
  --header 'If-None-Match: ETAG'
```

Сервис проверит ключ и вернёт временную ссылку на файл с данными региона в заголовке `Location`. Скачайте файл по этой ссылке. 

Также в ответе хранилища с файлом будет заголовок `ETag` — сохраните его значение. В последующих циклах [обновления данных](#update-data) вы можете сравнить сохранённый ETag с новым ETag из манифеста и не отправлять запрос, если они совпадают.

Возможные ответы:

| Код | Описание |
| --- | --- |
| 302 | Ключ действителен, данные изменились. Временная ссылка для скачивания указана в заголовке `Location`. |
| 304 | ETag совпадает: данные не изменились, скачивать файл не нужно. |
| 401 | Ключ не передан или неизвестен. |
| 403 | Ключ не прошёл проверку ограничений, заблокирован или не имеет доступа к региону. |
| 405 | Метод не поддерживается. |
| 429 | Слишком много запросов, повторите запрос позже. |
| 500 | Внутренняя ошибка сервера. |

### 5. Прочитайте данные {#use-data}

Скачанные файлы сжаты с помощью gzip и сериализованы в формате Protocol Buffers. Чтобы прочитать данные:

1. Распакуйте скачанные файлы.
2. Десериализуйте данные с помощью `.proto`-схемы. Для данных о дорожных сегментах и данных о дорожном трафике используются разные схемы.

<Tabs>
<TabItem value="catalog" label="Схема для данных о дорожных сегментах" default>

```json
syntax = "proto3";

package dgis.traffic.locations.v1;

// TrafficLocations содержит привязки расположения дорожных сегментов.
//
// Набор данных сопоставляет идентификатор каждого дорожного сегмента с его
// расположением. Значения road_segment_id можно использовать, чтобы связать этот
// набор данных с данными о трафике из dgis.traffic.flow.v1.
message TrafficLocations {
  // Данные о расположении дорожных сегментов.
  repeated LocationByRoadSegment locations_by_segment = 1;
}

// Данные о расположении одного дорожного сегмента.
message LocationByRoadSegment {
  // Уникальный идентификатор дорожного сегмента.
  //
  // Это значение совпадает с road_segment_id в наборе данных о трафике. По нему можно
  // сопоставить данные о скорости с расположением дорожного сегмента.
  uint64 road_segment_id = 1 [jstype = JS_STRING];

  // Информация о расположении дорожного сегмента.
  Location location = 2;
}

// Информация о расположении дорожного сегмента.
message Location {
  // Бинарная привязка расположения дорожного сегмента в формате OpenLR.
  //
  // Значение содержит данные OpenLR в бинарном виде.
  bytes openlr = 1;

  // Длина расположения в метрах.
  uint32 location_length_meters = 2;
}
```
</TabItem>
<TabItem value="dynamic" label="Схема для данных о дорожном трафике">

```json
syntax = "proto3";

package dgis.traffic.flow.v1;

// TrafficFlow содержит данные о трафике на дорожных сегментах конкретного региона.
message TrafficFlow {
  // Метаданные набора данных о трафике.
  TrafficFlowMetaInfo meta_info = 1;

  // Данные о трафике на дорожных сегментах.
  repeated TrafficDataByRoadSegment traffic_data = 2;
}

// Метаданные набора данных о трафике.
message TrafficFlowMetaInfo {
  // Версия набора данных о трафике.
  //
  // Значение основано на дате и времени создания набора данных.
  // Ожидаемый формат: YYYY-MM-DDTHH-MM-SSZ, например, 2026-07-22T00-00-00Z.
  string data_version = 1;

  // Название региона, для которого предоставлены данные о трафике.
  string region_name = 2;
}

// Данные о трафике на одном дорожном сегменте.
message TrafficDataByRoadSegment {
  // Уникальный идентификатор дорожного сегмента.
  //
  // По этому значению можно найти соответствующее расположение
  // в наборе данных о дорожных сегментах.
  uint64 road_segment_id = 1 [jstype = JS_STRING];

  // Признак того, что дорожный сегмент закрыт или недоступен для построения маршрутов,
  // например, из-за ремонта, перекрытия или других ограничений.
  bool road_locked = 2;

  // Информация о текущей скорости и состоянии трафика на дорожном сегменте.
  OnlineSpeed online_speed = 3;

  // Скорость свободного потока на дорожном сегменте.
  float freeflow_speed = 4;
}

// Информация о текущей скорости на дорожном сегменте.
message OnlineSpeed {
  // Текущая скорость движения в километрах в час.
  float speed_kmph = 1;

  // Расчётное время прохождения дорожного сегмента в секундах.
  int32 travel_time_seconds = 2;

  // Достоверность оценки скорости.
  //
  // Ожидаемый диапазон: от 0 до 100, где 0 — нет достоверности, 100 — максимальная.
  int32 confidence = 3;

  // Текущий цвет скорости на дорожном сегменте.
  SpeedColor speed_color = 4;
}

// Цвет скорости на дорожном сегменте.
enum SpeedColor {
  SPEED_COLOR_UNDEFINED = 0;
  SPEED_COLOR_DEEP_GREEN = 1;
  SPEED_COLOR_GREEN = 2;
  SPEED_COLOR_YELLOW = 3;
  SPEED_COLOR_ORANGE = 4;
  SPEED_COLOR_RED = 5;
  SPEED_COLOR_DEEP_RED = 6;
}
```

</TabItem>
</Tabs>

Где:

   * `data_version` — версия данных в формате `YYYY-MM-DDTHH-MM-SSZ` (UTC).
   * `region_name` — название региона.

* `traffic_data` — массив данных о дорожных сегментах:

   * `road_segment_id` — идентификатор дорожного сегмента.
   * `online_speed` — текущая ситуация на сегменте:

      * `speed_kmph` — скорость движения в км/ч.
      * `travel_time_seconds` — время прохождения сегмента в секундах.
      * `confidence` — достоверность оценки скорости от 0 до 100, где 0 — недостоверная, 100 — максимально достоверная. Рассчитывается по количеству устройств на участке дороги за период времени, по данным которых определена скорость движения. Чем больше устройств, тем выше значение.
      * `speed_color` — цвет скорости на сегменте. Он показывает, насколько скорость движения на сегменте отличается от скорости в условиях свободного потока (`freeflow_speed`).

        | Значение | Цвет | Описание |
        | --- | --- | --- |
        | `SPEED_COLOR_UNDEFINED` | — | Нет данных. |
        | `SPEED_COLOR_DEEP_GREEN` | Тёмно-зелёный | Свободное движение, скорость выше обычной. |
        | `SPEED_COLOR_GREEN` | Зелёный | Свободное движение, скорость близка к обычной. |
        | `SPEED_COLOR_YELLOW` | Жёлтый | Небольшое замедление, скорость немного ниже обычной. |
        | `SPEED_COLOR_ORANGE` | Оранжевый | Умеренный затор, скорость заметно ниже обычной. |
        | `SPEED_COLOR_RED` | Красный | Сильный затор, низкая скорость. |
        | `SPEED_COLOR_DEEP_RED` | Тёмно-красный | Движение почти стоит, очень сильный затор. |

   * `freeflow_speed` — скорость движения в км/ч на дорожном участке в условиях свободного потока: при низкой плотности трафика, без светофоров и заторов.
   * `road_locked` — признак того, что сегмент недоступен для построения маршрутов (например, закрыт из-за ремонта).

### 6. Сопоставьте данные с дорожным графом {#match-graph}

Чтобы использовать данные о трафике на вашем дорожном графе:

1. Сопоставьте сегменты с графом. Делайте это каждый раз, когда получаете новую версию данных о дорожных сегментах (не чаще раза в сутки):

    1. Для каждого сегмента декодируйте привязку в формате [OpenLR](https://www.openlr.org/location-referencing/) (`location.openlr`) и восстановите расположение сегмента на вашем дорожном графе.
    2. Сохраните соответствие между `road_segment_id` и участком графа.

2. Примените данные о трафике к дорожным сегментам. Делайте это при каждом получении новых данных о трафике (раз в минуту):

    1. Для каждого сегмента из `traffic_data` найдите участок графа по `road_segment_id` в сохранённом соответствии.
    2. Обновите данные сегмента: скорость, время прохождения и другие параметры из `online_speed`, а также `freeflow_speed` и `road_locked`.

## Обновление данных {#update-data}

Обновляйте данные о дорожном трафике раз в минуту, а о дорожных сегментах — не чаще раза в сутки. Для этого повторяйте цикл:

1. [Получите манифест](#get-manifest).
2. Для каждого региона сравните ETag из манифеста с ETag, которые вы сохранили при последнем получении данных этого региона:

    * `locations.etag` — с ETag данных о дорожных сегментах;
    * `traffic_flow.etag` — с ETag данных о дорожном трафике.

    Если ETag совпадают, у вас уже актуальная версия данных, и запрос на получение данных можно не отправлять.

3. Получите обновлённые данные о [дорожном трафике](#get-traffic) и [дорожных сегментах](#get-locations), у которых отличается ETag. После получения данных сохраните новые значения ETag из заголовка `ETag` ответа хранилища.
4. [Прочитайте](#use-data) полученные данные.
5. Если вы получили новые данные о сегментах, заново [сопоставьте](#match-graph) сегменты с вашим дорожным графом.
6. [Примените](#match-graph) данные о трафике к участкам графа.
