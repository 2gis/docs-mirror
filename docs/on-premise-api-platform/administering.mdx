# Обслуживание

Ниже представлены рекомендации по обслуживанию базовых сервисов и сервисов API-платформы.

## Резервное копирование инфраструктурных баз данных

<Tabs>
<TabItem value="core" label="Для базовых сервисов" default>

Резервное копирование рекомендовано только для баз PostgreSQL сервиса API-ключей, так как они содержат уникальные данные.

</TabItem>

<TabItem value="platform" label="Для API-платформы" >

* PostgreSQL: резервное копирование рекомендовано только для баз PostgreSQL сервиса Restrictions API, так как они содержат уникальные данные. Базы данных сервиса Catalog APIs не требуют резервного копирования. В случае потери данных вы можете [повторно импортировать их](/on-premise-api-platform/update/search#update-catalog-apis).

* Apache Cassandra: резервное копирование не требуется: в случае потери данных вы можете повторно импортировать их из S3-совместимого хранилища.

    :::note[Ускорение процесса восстановления]

    Восстановление данных через импорт может занять длительное время. Чтобы обеспечить минимальные значения RPO (Recovery Point Objective) и RTO (Recovery Time Objective), рекомендуется выполнять регулярное резервное копирование всех баз данных.

    :::

</TabItem>
</Tabs>
