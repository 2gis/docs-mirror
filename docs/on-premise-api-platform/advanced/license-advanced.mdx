# Продвинутые способы получения лицензии

В этом разделе описаны шаги получения лицензии в частных случаях, когда обычный способ недоступен.

## При обновлении сертификата сервера Kubernetes API или смене кластера {#kubernetes-certificate}

### Для версии базовых сервисов 2.13.0 и выше {#2-13}

Лицензия On-Premise привязана не к сертификату сервера Kubernetes API, а к данным в хранилище состояний сервиса лицензий (см. блок параметров `persistence` в конфигурационном файле [values-license.yaml](/on-premise-api-platform/installation#install-license-service)). 

Лицензия может быть бессрочной. Новая лицензия нужна, только если изменился состав сервисов в лицензии, сменилось хранилище состояний или утеряны его данные.

Если вы: 

* Обновили сертификат сервера Kubernetes API — текущая лицензия продолжит работать.
* Переносите сервис лицензий в другой кластер Kubernetes и сохраняете прежнее хранилище состояний — разверните сервис в новом кластере с теми же параметрами `persistence`. Не создавайте новый бакет и не копируйте в него содержимое старого. Сервис автоматически распознает действующую лицензию, получать новую не нужно. При необходимости перезапустите поды сервиса лицензий.
* Переносите сервис лицензий в новое хранилище состояний или потеряли данные хранилища — текущая лицензия работать не будет: см. раздел [При утрате данных хранилища или переезде в новое хранилище](#persistence-lost).

### Для версии базовых сервисов 2.12.0 и ниже {#2-12}

Лицензия On-Premise привязана к сертификату сервера Kubernetes API, поэтому после обновления этого сертификата или переезда на другой кластер Kubernetes вам необходимо получить новую лицензию On-Premise.

:::tip

Чтобы избежать простоя сервиса, вы можете заранее получить новую лицензию для нового сертификата сервера Kubernetes API. В этом случае сервис лицензий автоматически распознает новую лицензию, когда сертификат обновится.

:::

#### Если сервис не в состоянии простоя {#no-downtime}

1. Получите новый сертификат сервера Kubernetes API у администраторов вашей инфраструктуры.
2. Откройте директорию **license-dir** в S3-хранилище.
3. Откройте поддиректорию со старшим номером.
4. Замените файл `k8s-ca.crt` на новый файл сертификата, сохранив имя файла.
5. [Получите новую лицензию](/on-premise-api-platform/installation#get-license).

#### Если сервис уже в состоянии простоя {#downtime}

1. Откройте директорию **license-dir** в S3-хранилище.

2. Откройте поддиректорию со старшим номером.

3. Если директория содержит файл `license.txt`:

   1. Обратитесь в службу поддержки On-Premise с описанием проблемы, чтобы частично аннулировать лицензию на стороне <Brand />. Дождитесь подтверждения, что лицензия частично аннулирована.

      :::warning

      Не переходите к следующему шагу и не удаляйте никакие файлы, пока не получите подтверждение от службы поддержки On-Premise.

      :::

   2. Удалите файл `license.txt` и переходите к следующему шагу.

   Если файл `license.txt` отсутствует, переходите к следующему шагу.

4. <Tabs queryString="certificate">
   <TabItem value="over-1-29" label="Для версий 1.29.0 и выше" default>

   1. Удалите старый файл сертификата `k8s-ca.crt`.
   2. Перезапустите все поды сервиса лицензий.
   3. [Получите новую лицензию](/on-premise-api-platform/installation#get-license).
   4. Перезапустите все поды сервиса лицензий.

   </TabItem>
   <TabItem value="under-1-29" label="Для версий ниже 1.29.0">

   1. Получите новый сертификат сервера Kubernetes API.

      Для получения сертификата обратитесь к администраторам вашей инфраструктуры или найдите под, в спецификации которого есть параметр `automountServiceAccountToken: true` (например, это любой под API карт, если этот сервис установлен в окружении On-Premise) и выполните следующую команду:

      ```bash
      cat /var/run/secrets/kubernetes.io/serviceaccount/ca.crt
      ```

   2. Откройте директорию **license-dir** в S3-хранилище.

   3. Откройте поддиректорию со старшим номером.

   4. Замените файл `k8s-ca.crt` на новый файл сертификата, сохранив имя файла.

   5. [Получите новую лицензию](/on-premise-api-platform/installation#get-license).

   6. Перезапустите все поды сервиса лицензий.

   </TabItem>
   </Tabs>

## При утрате данных хранилища или переезде в новое хранилище {#persistence-lost}

Каждая лицензия специфична для окружения, где установлен программный комплекс On-Premise. Если данные хранилища состояний сервиса лицензий (см. настройки `persistence` в конфигурационном файле [values-license.yaml](/on-premise-api-platform/installation#install-license-service)) утеряны или вы переносите сервис в новое хранилище, текущая лицензия работать не будет, а получить новую обычным способом не получится.

Новое хранилище состояний должно быть пустым: не копируйте в него данные из старого хранилища (например, с помощью `mc mirror` или `aws s3 sync`).

Выполните следующие шаги:

1. Обратитесь в службу поддержки On-Premise, чтобы аннулировать лицензию на стороне <Brand />. Дождитесь подтверждения, что лицензия аннулирована.

   :::warning

   Не переходите к следующему шагу и не удаляйте никакие файлы, пока не получите подтверждение от службы поддержки On-Premise.

   :::

2. Удалите сервис лицензий из окружения, где установлен программный комплекс On-Premise.

3. Внутри S3-хранилища артефактов установки (не хранилища состояний) удалите содержимое директории **license-dir**, кроме файла `type` (находится в корне директории).

   Если файл `type` случайно удалён, вы можете восстановить его командой [`dgctl pull`](/on-premise-api-platform/overview/2gis-cli/usage#scenario-pull-to-s3) с указанием аргумента `--only-license`. Если при этом в окружении нет хоста с доступом в интернет, используйте [дополнительный хост](/on-premise-api-platform/installation#get-license) для копирования файлов.

4. Установите сервис лицензий, указав в параметрах `persistence` пустое хранилище состояний, и запросите новую лицензию [обычным способом](/on-premise-api-platform/installation#install-license).

## При утрате узла с запущенным сервисом лицензий {#node-lost}

:::note[Только для типа лицензирования 2]

Этот способ подходит, если в конфигурационном файле для [установки сервиса лицензий](/on-premise-api-platform/installation#install-license) указан параметр `license.type: 2`.

:::

Лицензия типа 2 является специфичной для физических узлов, на которых запущен сервис лицензий. Если один из узлов был потерян, получите новую лицензию следующим способом:

1. Обратитесь в службу поддержки On-Premise, чтобы аннулировать лицензию на стороне <Brand />. Дождитесь подтверждения, что лицензия аннулирована.

   :::warning

   Не переходите к следующему шагу и не удаляйте никакие файлы, пока не получите подтверждение от службы поддержки On-Premise.

   :::

2. Внутри S3-хранилища удалите директорию **license-dir/1**.

3. Добавьте новый физический узел для запуска сервиса лицензий и обновите настройки, чтобы сервис лицензий появился на новом узле.

4. Скопируйте недостающие файлы `csr-N.csr` и `csr-N.signature` из поддиректории **license-dir** со старшим номером в **license-dir/1**.

   `N` в именах файлов — 0 или 1 в зависимости от того, какой узел был утерян.

5. Внутри S3-хранилища удалите все директории кроме **license-dir/1**.

6. [Получите новую лицензию](/on-premise-api-platform/installation#get-license).

7. Перезапустите все поды сервиса лицензий.

## При смене ключа или типа лицензирования {#key-changed}

Состояние сервиса лицензий зависит от ключа и типа лицензирования. Если ключ или тип меняются, старое состояние будет мешать дальнейшей работе сервиса. Выполните следующие шаги:

1. Удалите сервис лицензий из окружения, где установлен комплекс On-Premise.

2. Если ключ не менялся, обратитесь в службу поддержки On-Premise, чтобы аннулировать лицензию на стороне <Brand />. Дождитесь подтверждения, что лицензия аннулирована.

3. Внутри S3-хранилища удалите всё содержимое директории **license-dir**, кроме файла `type` (находится в корне директории).

   Если файл `type` случайно удалён, вы можете восстановить его командой [`dgctl pull`](/on-premise-api-platform/overview/2gis-cli/usage#scenario-pull-to-s3) с указанием аргумента `--only-license`. Если при этом в окружении нет хоста с доступом в интернет, используйте [дополнительный хост](/on-premise-api-platform/installation#get-license) для копирования файлов.

4. Удалите директорию с данными для хранения состояний сервиса лицензий.

5. Установите сервис лицензий и запросите новую лицензию [обычным способом](/on-premise-api-platform/installation#install-license).
