# API поиска

Сервисы поиска позволяют получать информацию об объектах: организациях, зданиях, общественных местах и т. д.

## Архитектура {#architecture}

Сервисы поиска состоят из двух сервисов:

* Catalog APIs предоставляют RESTful APIs для конечных пользователей и приложений.
* Search API — поисковый движок, который обрабатывает запросы от Catalog APIs.

Search API v8 — обновлённая версия Search API с повышенной точностью поисковой выдачи. Search API v8 находится на стадии бета-тестирования.

**Взаимодействие компонентов Search API v8**

**Catalog APIs** отправляет HTTP-запрос в **IngressRouter**. **IngressRouter** отправляет запрос в **SegmentDetector**, который дополняет его данными из запрашиваемых сегментов, а затем передаёт в **Head**. **Head** разбивает запрос на части и отправляет их группе **Unisearcher**. Каждый **Unisearcher** в группе ищет данные в доступных ему индексах и возвращает результат в **Head**. **Head** собирает ответы и передаёт их в **IngressRouter**, который возвращает результат в **Catalog APIs**.

**Controller** проверяет наличие новых версий фидов (исходных данных) и выдаёт задания на индексацию. **DataAdapter** и **Indexer** обращаются к **Object Storage** (S3-совместимому хранилищу, в котором находятся исходные фиды), получают оттуда фиды и индексируют их. Готовые индексы сохраняются в **FilesStorage**, откуда их получают остальные сервисы. Индексы обновляются в реальном времени, без перезапуска сервисов.

Подробнее об установке сервисов поиска с обновлённой версией Search API см. в разделе [Установка API для работы с поиском (с Search API v8)](/on-premise-api-platform/advanced/search-v8).

## Зависимости {#dependencies}

* **Для Search API и Search API v8**

  * Хранилище артефактов установки.

* **Для Catalog APIs**

  * Общая инфраструктура:

    * Хранилище PostgreSQL для хранения данных об объектах (с расширением PostGIS).

      :::tip[Можно использовать аналог из реестра Минцифры]

      Доступные аналоги PostgreSQL, включённые в реестр Минцифры, см. в разделе [Системные требования](/on-premise-api-platform/requirements).

      :::

  * Сервисы:

    * Сервис лицензий.
    * Сервис API-ключей.
    * Сервис сбора статистики.
    * Search API.

Подробнее о том, как проверить требования для каждого сервиса, см. в документе [Системные требования](/on-premise-api-platform/requirements).
